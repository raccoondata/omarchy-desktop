# Taskbar icons

The taskbar (`~/.config/omarchy/bar/modules/taskbar.qml`) draws every window
with one line icon, recoloured at runtime: theme foreground when inactive,
accent when focused, faded when minimized. So each app needs exactly **one**
drawing, covering both themes and every state.

**Read `ICON-SPEC.md` (next to this file) first**: the drawing rules (grid,
live area, balance, stroke, fills, elements), the style, and the script
format. Every icon is `<name>.icon.py`: a docstring saying what it depicts,
iconkit builders and geometry helpers, and `icon(...)`. Never write a bare
SVG body into an icon file, and never edit `taskbar-icons.js` or
`taskbar-icons.json` by hand: they're built from the scripts.

The tools are in `scripts/` (all Python on `scripts/iconkit.py`, all `-h`):
`icon-new`, `icon-preview`, `icon-lint`, `icon-set`, `icon-build`,
`icon-test`. `vmouse` is a separate helper: a virtual mouse for clicking the
taskbar in tests.

## Workflow

1. **Find what to match**, and check the icon doesn't exist
   (`scripts/icon-set --list`).
   - Desktop app: its window class, `hyprctl clients -j | jq -r '.[].class'`
     with it open, or `StartupWMClass=` in its `.desktop` file. Don't guess:
     VS Code is `com.microsoft.VSCode`, not `code`.
   - Omarchy web app: `chrome-<host>__<path>-Default` (from the URL in its
     `.desktop` Exec line), e.g. `chrome-youtube.com__-Default`.
   - Terminal program: the foreground process name (`comm`), as
     `~/.config/omarchy/window-programs` reports it.

2. **Draw it** in a scratch folder: `scripts/icon-new <name> "<what it
   depicts>"`, then edit `<name>.icon.py`. Look at the real logo first
   (`find /usr/share/icons /usr/share/pixmaps -iname '*<app>*'`, agent marks
   in `/usr/share/omarchy/shell/plugins/agents/assets/`), and at a few
   existing scripts for weight and family (the sources folder, see
   ICON-SPEC.md > Where things live).
   - Preview big and at real size in both colours:
     `scripts/icon-preview <out.png> <name>.icon.py` and Read the PNG. It
     lists spec problems too.
   - Unsure? Draft alternatives as `<name>-b.icon.py`, `<name>-c.icon.py`
     and preview them together. Iterate until it reads at 23px.
   - Computed geometry (rays, arcs, rotations) goes in the script with its
     parameters named at the top, never pasted in as numbers from elsewhere.

3. **Install it**: `scripts/icon-set <name> <name>.icon.py`. It refuses spec
   errors, installs the script, keeps the drafts named after the icon, and
   builds. Where it goes depends on the PC:
   - **Usually: your own icons** (`~/.config/omarchy/taskbar-icons-src/`,
     built into `~/.config/omarchy/taskbar-icons.json`, which desktop updates
     never touch). Say which windows get it in the same command:
     `--program <prog>` for a terminal program, `--class '<regex>'` for a
     window class (both repeatable; checked before the built-in rules).
   - **The maintainer's PC** (`maintainer=on` in
     `~/.config/omarchy/desktop.conf`): the built-in set in the
     omarchy-desktop repo, which ships to everyone. Then map it by hand in
     `taskbar.qml`: `programIcons` (`program: "icon"`) for terminal
     programs, `classIcons` (`[/regex/, "icon"]`, first match wins; specific
     rules above general ones, web app hosts above the generic browser rule,
     exact classes as `^...$`). `--user` forces your own icons there too.

4. **Reload and test**: `omarchy restart shell`, check the log for taskbar
   errors, then `scripts/icon-test <out.png> <class>...` (throwaway windows,
   a screenshot of the real bar). Read it and confirm each shows the icon.

5. **Tell the user** what it looks like and what it's matched on. Clean up
   the scratch folder (icon-set kept the drafts).

To change an existing icon: copy its script from the sources folder into a
scratch folder, edit, preview, `icon-set` it back. To check everything:
`scripts/icon-lint`, and `scripts/icon-build --check` (the built file matches
the scripts).

## Gotchas

- The bar doesn't hot-reload icons or `taskbar.qml`: `omarchy restart shell`
  after installing. `shell.json` does hot-reload.
- Check for errors with:
  `qs log --id $(ls -t $XDG_RUNTIME_DIR/quickshell/by-id/ | head -1) | grep -iE 'taskbar|modules/'`
- Lessons: a 12-ray Claude burst clumped, a tapered version blobbed, a
  ChatGPT knot read as a camera aperture. Fewer, bolder strokes.
- `icon-test`: Ghostty only takes dotted classes without `@`; anything else
  opens in foot. A class Omarchy makes fullscreen (Moonlight) hides the bar.
